# 修改流程

针对已有 Skill 的修改流程，同样从初始化开始，循环审核直至通过。

## 步骤

1. **初始化工作空间**（同 [初始化](../初始化/初始化.md)）：
   - 读取当前目录，询问用户工作空间目录
   - 检查是否一致，不一致则尝试切换
   - 建立所需文件夹（含 `tmp/`）
   - 标记「初始化完成」，写入 `tmp/progress.md`

2. **标记初步流程大纲建立完成**，进入约束检查。

3. **约束检查**（同 [分支分析](../分支分析/分支分析.md)）：
   - 约束是否缺失 → 建约束表
   - 逻辑是否一致 → 不符合则回查
   - 约束是否丢失 → 丢失则回查
   - 大纲是否完整 → 不完整则重建
   - 是否有重复行为 → 有则生成脚本
   - 目录是否完整 → 不完整则重建
   - 分支是否可达 → 否则修复

4. **按用户需求修改**：
   - 执行修改后进入循环审核
   - 审核是否通过？否 → 回到修改步骤
   - 是 → 进入下一步

5. **完成修改并进行项目信息修正**：
   - 更新 README、CHANGELOG 等
   - 执行 git 操作

6. **标记「项目修改完成」**，流程结束。

## 决策点

- 目录一致？（不一致 → 切换）
- 切换成功？（否 → 提示用户）
- 审核通过？（否 → 重新修改）
