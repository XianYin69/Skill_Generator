# git 工作流约束

本项目（Skill_Generator）的开发工作流采用严格的功能分支策略，每一步操作均须遵循以下规则，以保障分支历史可追溯、可回滚、可合入。

## 规则

1. **启动前拉取**：开始任何工作前，确认远端是否有更新（`git fetch`）；若有，优先执行 `git pull --ff-only`，不得忽略远端更新直接工作。
2. **功能分支提交**：每个步骤完成后，必须在本步骤对应的功能分支上提交（`feature/<topic>`），功能分支名不得为 `main` 或 `dev`。
3. **功能审核通过后合并到 dev**：双链辩论（logic_chain.py debate）与 check-links 悬空链接为 0 后，将本步骤功能分支合并到 `dev`。
4. **整体项目审核通过后推送**：九项审查标准全部通过后，将 `dev` 合并到 `main`，并将 `main` 与 `dev` 一起推送至远端（`git push origin main dev`）。
5. **禁止直写 main/dev**：所有变更必须经由功能分支进入 `dev`，`main` 与 `dev` 不接受直接 commit。
6. **重试熔断**：任一审查步骤失败且重试次数达 10 次，触发惩罚机制熔断（penalty.py），强制回退当前功能分支或向用户求助。

## 违规后果

- 跳过功能分支：main/dev 被污染，无法按步骤回滚；
- 忽略远端更新：本地与远端分叉，merge 时出现冲突；
- 跳过审核：问题代码直接进主分支并发布，破坏约束。
