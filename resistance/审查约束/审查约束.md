# 审查约束（整体审查得出的项目级约束）

> 依据 [整体审查](../../branch/流程/整体审查/整体审查.md) 分支对本项目的实测结论固化而成。
> 每条对应一处真实风险；违反后果见末尾。

## 审查发现 → 约束

1. **完整性**：流程 11 步全部有子节点、根索引与后继链，无孤立文档。
   → 约束：新增节点必须入根索引并可从入口遍历到达。
2. **规范（.md ≤50 行）**：50 行红线只约束 markdown 文本；`.py` 等脚本不限行数（用户裁定，原「超 50 行已修」仅作沿革记录）。
   → 约束：所有 `.md` 正文 ≤ 50 行，超出须拆「总索引 + 子文件」；脚本 `.py/.ps1/.sh/.cmd` 不限行数，建议按职责拆「入口 + 模块」，仍禁裸 except、print 调试残留、>100 字符长行、超长函数。
3. **可达性**：跨步骤链接深度易错（`../` 级数），须以 check-links 验证。
   → 约束：任何增删移动后运行 `python scripts/check-links.py`，悬空必须为 0。
4. **命名合规**：文件夹=流程名，markdown/其他文件=流程名+扩展名，脚本用英文名。
   → 约束：中文流程节点用中文名，`scripts/` 下用英文名。
5. **安全/版权**：知识库下载须保留许可与版权，来源限开放库/百科/权威论坛博客/MIT 仓库。
   → 约束：无 `.provenance.json` 的素材不得入库；非 MIT 仓库降级或拒用。
6. **健壮性/兜底**：重试与漫游须计数熔断（惩罚机制），过程链可回滚。
   → 约束：调用 penalty/process_chain，不静默吞异常。

7. **依赖可追溯**：曾有依赖无原始链接，无法核实许可与来源。
   → 约束：`dependence/deps.json` 每条必附 `source_url`，缺项即不合格；整体审查运行 `python scripts/lint-deps.py --root .`，rc≠0 不得通过。

8. **计划任务边界**：技能自行轮询执行计划任务会与 SMS 调度器重复触发。
   -> 约束：planned_tasks/ 只作声明，一任务一文件 pt-<skill>-<slug>.json，schema 字段名不得改动；到期由 SMS 调度器执行并挂 session 关联链，技能自身不得执行。

## 未通过项处置

记录未通过项 → 选择跳回对应步骤 → 循环审查直至九项全过，再标记项目审核完成。
