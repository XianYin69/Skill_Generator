# 04_分支分析

对大纲的每个分支进行约束、逻辑、完整性检查。

## 步骤

对大纲的每个分支依次执行以下检查：

1. **约束检查**：分支的约束是否缺失？
   - 缺失 → 记录缺失点，建立《约束表》（参考 [07_约束编写](../07_约束编写/)），回到约束编写阶段
   - 不缺 → 进入下一步
2. **逻辑一致性**：是否符合原分支逻辑？
   - 不符合 → 重定向回 [02_经验查询](../02_经验查询/)
   - 符合 → 进入下一步
3. **约束是否丢失**：约束表中条目是否完整保留？
   - 丢失 → 重定向回 [02_经验查询](../02_经验查询/)
   - 未丢失 → 进入下一步
4. **大纲完整性**：初步流程大纲是否被篡改或丢失？
   - 是 → 重建初步流程大纲，回到 [03_大纲构建](../03_大纲构建/)
   - 否 → 进入下一步
5. **重复行为检查**：流程中是否有重复交互行为？
   - 有 → 记录重复行为，进入 [05_脚本构建](../05_脚本构建/) 生成对应 Python 脚本
   - 无 → 进入下一步
6. **整体审核**：审核整个 Skill 结构。
   - 目录是否完整？不完整 → 重建目录（见下文）
   - 所有分支逻辑是否可达？否 → 修复缺失/多余分支

### 重建目录

- 询问用户需求，明确目录结构
- 按需求重建，回到 [01_需求确认](../01_需求确认/)

## 决策点

- 约束缺失？（是 → 建约束表）
- 逻辑一致？（否 → 回查）
- 约束丢失？（是 → 回查）
- 大纲完整？（否 → 重建）
- 有重复？（是 → 生成脚本）
- 目录完整？（否 → 重建）
- 分支可达？（否 → 修复）
